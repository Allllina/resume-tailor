# JD 拆解方法论

当用户提供了具体JD时，按以下结构化流程拆解。

## 拆解框架

将JD拆解为5个层次：

### 1. 岗位核心定位
一句话总结这个岗位要做什么。
- 格式："这个岗位的核心是 [做什么]，服务于 [谁]，目标是 [什么结果]"
- 示例："这个岗位的核心是用AI技术优化HR业务流程，服务于京东HR团队，目标是提升工作流效率与用户体验"

### 2. 硬性要求
必须满足的门槛条件，通常在"任职资格/Requirements"中明确列出：
- 学历和专业要求
- 工作年限
- 必备技能/工具/语言
- 证书/资质

评估方式：逐条对照简历，标注 ✅满足 / ❌不满足 / ⚠️部分满足

### 3. 核心能力要求
JD中反复强调或放在前面位置的能力，通常3-5条。识别方法：
- JD工作内容的前2-3条通常是最核心的
- 多次出现的关键词（如"数据分析"出现3次）
- 动词的力度暗示优先级（"负责">"参与">"了解"）

每条核心能力需要标注：
- 能力描述
- JD中的原文依据
- 简历中的对应经历（如果有）

### 4. 加分项
Preferred/优先条件中列出的内容，不是硬性要求但有会更好：
- 特定行业经验
- 特定工具/技术
- 软性能力（领导力、跨文化等）

### 5. 行业/领域关键词
JD中出现的专业术语、产品名、技术栈，按类别整理：
- 行业术语（如"CDISC"、"铁三角"、"AARRR"）
- 技术栈（如"R Shiny"、"LangChain"、"Salesforce"）
- 公司/产品名（如"京东健康"、"CUPCAKE"）

这些关键词用于Step 6重写时融入目标语言。

## 匹配预设Scenario

拆解完成后，检查JD是否与已有scenario匹配：
- 如果匹配 → 加载该scenario作为补充参考，但以JD为主要优化依据
- 如果不匹配 → 不加载任何scenario，完全基于JD+通用规则优化
- 如果部分匹配（如JD是"AI+HR"，匹配ai-innovation但缺HR语境） → 加载最近似的scenario，标注差异

## 多JD模式的拆解

当用户提供多个JD时，分别拆解每个JD，然后提取：

### 共性要求
所有JD都要求的能力 → 简历中必须强势体现

### 差异化要求
只有部分JD要求的能力 → 尽量覆盖但不为一个JD牺牲其他

### 冲突点
不同JD之间矛盾的包装方向 → 明确告知用户取舍
- 示例：咨询JD要求保守格式，互联网JD允许现代风格 → 选保守（兼容性更好）
- 示例：一个JD要英文简历，其他要中文 → 建议分两份

### 最大公约数策略
确定简历的整体叙事基调：
- 哪些经历是所有JD的通用弹药
- 哪些经历需要选择性强调
- 整体基调偏向哪个方向（通常偏向竞争力最强的方向）
